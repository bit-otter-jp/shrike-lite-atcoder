# ABC470D Baseline 設計メモ

## 1. 問題の整理

長さ `N` の順列に対し、次の `Q` クエリを順番に処理する。

- `1 x y`: 現在の順列の位置 `x`, `y` にある値を交換する。
- `2`: 現在の順列を逆順列に置き換える。

制約は `2 <= N <= 500000`, `1 <= Q <= 500000`。入力形式と公式サンプルは AtCoder の
[ABC470 D - Inverse and Swap](https://atcoder.jp/contests/abc470/tasks/abc470_d?lang=ja)
に従う。

## 2. `P` / `Pinv` / 向き状態

物理配列 `p` と `pinv` を常に互いの逆順列として保持する。

```text
pinv[p[i]] = i
p[pinv[i]] = i
```

1 bit の `inverted` を用意し、論理的な現在の順列を次のように表す。

```text
inverted == 0: current[i] = p[i]
inverted == 1: current[i] = pinv[i]
```

クエリごとの更新は以下のとおり。

### `2`

`inverted` を反転するだけでよい。配列全体はコピーしない。

### `1 x y` (`inverted == 0`)

クロック開始時の `a = p[x]`, `b = p[y]` を使い、同一クロックで次を更新する。

```text
p[x]    <- b
p[y]    <- a
pinv[a] <- y
pinv[b] <- x
```

### `1 x y` (`inverted == 1`)

クロック開始時の `a = pinv[x]`, `b = pinv[y]` を使い、同一クロックで次を更新する。

```text
pinv[x] <- b
pinv[y] <- a
p[a]    <- y
p[b]    <- x
```

どちらの場合も更新後に `p` と `pinv` の逆順列関係が保たれる。

## 3. クロック単位データフロー

入力ロードは `TIME=0` に行い、論理クロック数に含めない。

| 論理クロック | 処理 |
|---:|---|
| 1 | 全 `i` の `pinv[p[i]] <- i` を一括実行し、逆順列を生成 |
| 2 .. `Q+1` | 入力順に1クロックあたり1クエリを処理 |
| `Q+2` | 全 `i` の `answer[i] <- (inverted ? pinv[i] : p[i])` を一括実行 |

回答格納後の出力ループには遅延もクロック待ちも入れず、同一シミュレーション時刻で出力する。

Verilog の `for` ループは Icarus 上の記述・実行手段として逐次評価されるが、この計算モデルでは、ループ本体が互いに独立な組み合わせ回路／レジスタ群を表すため1論理クロックと数える。実実行時間は論理クロック数とは別に測定する。

## 4. 同一クロック Write 競合の確認

- 逆順列生成: 初期 `p` は順列なので、各 `p[i]` は相異なり、`pinv[p[i]]` の書込先は重複しない。
- 型1、通常向き: `x != y`。順列なので `a = p[x]` と `b = p[y]` も異なる。従って `p[x]` / `p[y]` および `pinv[a]` / `pinv[b]` はそれぞれ別の書込先である。
- 型1、逆向き: 同様に `pinv[x] != pinv[y]` なので、`pinv[x]` / `pinv[y]` および `p[a]` / `p[b]` はそれぞれ別の書込先である。
- `p` と `pinv` は別配列なので、両者の添字が数値として同じでも競合しない。
- 回答格納: 各反復は別々の `answer[i]` だけに書き込む。
- 型2: `inverted` だけに1回書き込む。

したがって、各クロックで同一状態への競合 Write はない。

## 5. 内部データ構造

最大制約を静的上限とする SystemVerilog 配列を使用する。

- `integer p[1:MAX_N]`: 基準向きの順列
- `integer pinv[1:MAX_N]`: `p` の逆順列
- `integer answer[1:MAX_N]`: 完了条件となる回答レジスタ
- `reg [1:0] query_type[0:MAX_Q-1]`: 全クエリの種類
- `integer query_x[0:MAX_Q-1]`, `query_y[...]`: 型1の引数
- `reg inverted`: 現在向き
- フェーズ、クエリ添字、論理クロックカウンタ

値と添字は最大 500000 なので32 bit整数で十分である。未使用の型2クエリ引数は参照しない。

## 6. テスト計画

1. 公式サンプル3件を照合する。
2. 小規模なランダム順列・ランダムクエリを生成し、配列を直接反転する Python 参照実装と比較する。
3. 境界ケースを確認する。
   - 最小 `N=2`, 最小 `Q=1`
   - 型1だけ、型2だけ
   - 最初／最後の位置の交換
   - 型2の偶数回・奇数回
   - 型2の直前直後に型1
4. `N=Q=500000` かつ全クエリが型1のケースを最大規模性能試験とする。型2より配列更新数が多いため Baseline の実行負荷確認に適する。
5. 性能試験で、論理クロック数、`vvp` の実時間、プロセスの最大 Working Set を記録する。

## 7. `Q + 2 clocks` の説明

逆順列生成が1クロック、クエリが `Q` クロック、回答レジスタへの一括格納が1クロックなので、合計は厳密に

```text
1 + Q + 1 = Q + 2 clocks
```

となる。入力ロードと回答レジスタ完成後の標準出力は計数外である。

## 8. 設計妥当性の結論

各クロック後に「`p` と `pinv` は互いに逆順列」という不変条件が維持され、`inverted` が論理的な現在向きを一意に定める。型1は4要素だけ、型2は1 bitだけを更新し、どのケースにも同一配列・同一添字への競合 Write はない。最後に向き状態に従って全回答レジスタを一括格納できるため、仕様の正しさと `Q+2` クロックを両立する Baseline 設計として妥当である。

なお、実FPGAの配線・ポート数・タイミングは対象外であり、大規模 `for` ループの Icarus 実時間とメモリは性能試験で別途評価する。
