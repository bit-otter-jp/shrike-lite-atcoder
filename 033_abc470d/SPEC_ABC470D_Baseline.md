# Icarus理想FPGA版 AtCoder 実装指示

## 1. 基本ルール

この実装は実FPGAへの合成を目的としない。

AtCoderのVerilog 2012 / Icarus Verilog環境上で、クロック数を独自の評価指標としてAtCoder問題を解く。

### 計算モデル

- 入力はシミュレーション時刻 `TIME=0` で標準入力からすべて読み込んでよい
- 入力読み込みに必要な処理はクロック数に含めない
- 問題を解く処理はクロック駆動とする
- 組み合わせ回路として表現できる処理は、クロック数上は時間コスト0とする
- LUT数、配線遅延、MUX規模、Fmaxなど、実FPGAの物理制約は考慮しない
- 大規模なレジスタ配列、大量の比較器・演算器などを使用してよい
- 同一クロックで互いに独立な処理は並列実行してよい
- 同一状態への競合Writeは原則禁止する
- IcarusがAtCoderのメモリ制限・実行時間制限内で処理できることは必要
- クロック数とIcarus上の実実行時間は別の指標として記録する

### 完了条件

問題ごとに回答レジスタを用意する。

最終回答が回答レジスタへ格納されたクロックを「計算完了」とする。

その後の `$write` / `$display` による標準出力はクロック数に含めない。

### 実装方針

最初から極端な最適化版を作らない。

1. 単純なクロック駆動Baselineを実装
2. 正しさを確認
3. クロック数を測定
4. 並列化版を追加
5. 必要なら先読み・スケジューリングなどを追加

各段階は独立して比較可能な状態を残す。

### テスト

最低限、以下を実施する。

- AtCoder公式サンプル
- 小規模ランダムケース
- Python等の参照実装との結果比較
- 境界ケース
- 最大規模を想定した性能試験

性能試験では最低限、

- 論理クロック数
- `vvp`実行時間
- 最大メモリ使用量

を記録する。

# 2. 問題特有：ABC470D Baseline

## 目的

ABC470Dを、まず単純なクロック駆動回路として実装する。

この段階ではクエリ並列化や先読み最適化を行わない。

目標クロック数は、

`Q + 2 clocks`

とする。

## TIME=0：入力ロード

標準入力から以下をすべて読み込み、内部レジスタへ保持する。

- `N`
- `Q`
- 初期順列 `P`
- 全クエリ

この入力ロードはクロック数に含めない。

## Clock 1：逆順列生成

逆順列 `Pinv` を生成する。

すべての `i` について、

`Pinv[P[i]] = i`

を同一クロックで並列に実行する。

`P` は順列なのでWrite先は競合しない。

N回の逐次処理にはしない。

**最大500,000要素でも1クロックで生成する。**

## Clock 2 ～ Q+1：クエリ処理

Baselineでは1クエリを1クロックで処理する。

`P` と `Pinv` の両方を常に保持し、クエリ内容に応じて必要な状態を更新する。

逆順列化操作については、可能なら配列全体をコピーせず、どちらの表を現在の順列として扱うかを示す状態で表現する。

詳細な状態更新方法は、問題仕様からCodex側で整理すること。

## Clock Q+2：回答格納

最終状態に応じた回答を、

`answer[1:N]`

へ同一クロックで一括格納する。

N要素を逐次コピーしない。

このクロックで計算完了とする。

## 標準出力

回答レジスタ完成後はシミュレーション時刻を進めず、

`answer[]`

を標準出力へ出力して終了する。

標準出力処理は論理クロック数に含めない。

# 3. Codexへの最初の作業

いきなり実装を開始せず、まず以下を作成すること。

1. ABC470Dの処理内容の短い整理
2. `P` / `Pinv` / 向き状態の更新方法
3. Baselineのクロック単位データフロー
4. 同一クロックWrite競合がないことの確認
5. 想定する内部データ構造
6. テスト計画
7. `Q + 2 clocks`になることの説明

この設計メモを作成した後、その設計に基づいてVerilog実装とテストを行う。

実装完了後は、

- サンプル結果
- ランダム比較結果
- 最大ケース試験
- 論理クロック数
- `vvp`実行時間
- 最大メモリ使用量
- 発見した問題点

を報告すること。

次段階の並列化はまだ実装しない。
