# ABC471E AtCoder Verilog - WORK_REQUEST

## 1. 目的

AtCoder ABC471E を **Verilog 2012 / Icarus Verilog** で解き、AtCoder提出用コードとしてACを狙う。

今回はFPGA実装ではない。

```text
FPGAへの合成可能性
回路面積
PNR
タイミング制約
実機動作
```

は評価対象外とする。

Verilogを競技プログラミング言語として使用する。

---

## 2. 問題条件

元のABC471Eの問題条件をそのまま扱う。

```text
MOD = 998244353
N <= 200000
1 <= K <= N
Ai <= 10^9
```

入力は標準入力から読み、答えを標準出力へ出力する。

---

## 3. 使用してよい機能

Icarus Verilog上で利用できる機能は、合成可能性を気にせず使用してよい。

例えば、

```text
64bit整数
*
/
%
for
while
function
task
配列
```

などを必要に応じて使用してよい。

FPGA版で使用した逐次modular multiplier等を再現する必要はない。

---

## 4. 数学的な基準式

FPGA版では、次の式を使用した。

```text
prefix_sum  = ΣAi
square_sum  = ΣAi^2

pair_twice =
    prefix_sum^2 - square_sum

answer =
    C(N-1,K-1) * square_sum
  + C(N-2,K-2) * pair_twice
  mod 998244353
```

この式をそのまま使ってもよい。

ただし、**Icarus上でより単純または高速な方法がある場合は変更してよい。**

今回の評価基準はFPGA版との構造一致ではなく、AtCoderで正しい答えを時間内に出すことである。

---

## 5. 実装方針

まず、理解しやすいBaselineを作る。

優先順位:

```text
1. 正しさ
2. AtCoder制限内の実行時間
3. メモリ使用量
4. コードの単純さ
```

FPGA向け最適化は行わない。

---

## 6. 検証

最低限、次を実施する。

### 6.1 公式サンプル

ABC471Eの公式サンプルをすべて確認する。

### 6.2 独立ランダムテスト

小さいNについて、Python等で全組合せを列挙する独立実装を作り、Verilog版と比較する。

期待値生成側でVerilog版の式をそのまま写しただけの実装にはしない。

### 6.3 境界ケース

少なくとも次を確認する。

```text
N=1, K=1
K=1
K=N
Ai=0
Ai=1
Ai=10^9
同じ値が並ぶケース
```

---

## 7. 最大ケース測定

正しさ確認後、

```text
N = 200000
```

の最大規模ケースを生成し、AtCoder提出時と同等のIcarus実行条件で測定する。

記録するもの:

```text
実時間
Peak Working Set
出力の正しさ
```

可能なら複数回測定し、ばらつきも確認する。

---

## 8. 高速化

Baselineが実時間上厳しい場合のみ、高速化へ進む。

候補例:

```text
入力処理の高速化
mod演算回数の削減
組合せ係数計算の整理
不要な配列の削除
```

ただし、最初から過剰な最適化はしない。

変更後は必ずランダムテストと最大ケース測定を再実行する。
