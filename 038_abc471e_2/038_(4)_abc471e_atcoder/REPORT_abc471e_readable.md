## コードの構造

入力 `x` ごとに、前編の導出と同じ順序で次の 3 値を更新する。

```verilog
x = x % MOD;

pair_sum = (pair_sum + prefix_sum * x) % MOD;
prefix_sum = (prefix_sum + x) % MOD;
square_sum = (square_sum + x * x) % MOD;
```

`pair_sum` の更新時点では `prefix_sum` が以前の要素の和なので、各非順序対の積を
ちょうど 1 回ずつ加算する。その後に現在の `x` を `prefix_sum` へ加える。

最終式も導出と直接対応する。

```text
C(N-1,K-1) * square_sum
+ 2 * C(N-2,K-2) * pair_sum
```

`C(N-1,K-1)` は分子積、分母積、Fermat の小定理による分母逆元で求める。
`K>=2` では、コメントに式を明記したうえで次の関係を利用する。

```text
C(N-2,K-2) = C(N-1,K-1) * (K-1) / (N-1)
```

`K=1` は pair の寄与を 0 として分岐する。剰余乗算は signed 64 bit で行い、2 項の
積は `10^18` 未満なのでオーバーフローしない。

計算量は `O(N + min(K-1,N-K) + log MOD)`、追加メモリは `O(1)` である。

| テスト | 件数 | 結果 |

| 固定 seed の独立ランダム | 300 | PASS |

境界ケースには `N=1,K=1`, `K=1`, `K=N`, `Ai=0`, `Ai=1`, `Ai=10^9`, 同値列、
`MOD-1`, `MOD`, `MOD+1` を含めた。`Ai=0` は公式制約外だが作業指示に従っている。

ランダム oracle は Verilog の集約式を使用せず、小さい N の K 要素部分集合をすべて
列挙し、それぞれの和を二乗して合計する。seed は `47100005`。

コードテスト入力は SHA-256
`1ed80be11d579b6d34e3e382d88a0bc61125ee34d04ce1983b548d40fafea73c` を確認し、
期待値 `379620342` と一致した。終了コード 0、stderr は空、stdout は答え 1 行だけだった。

## 既存最適化版との比較

行数は LF/CRLF に関係しない物理行数を主値とし、参考として空行とコメントだけの行を
除いた行数も併記する。既存版の性能値は `MEASUREMENT_abc471e_verilog.md` の最終版
3 回測定から引用した。

| 項目 | 3レジスタ記事版 | 既存最適化版 |
|---|---:|---:|
| 主要集計値数 | 3 | 2 |
| `pair_sum` 保持 | あり | なし |
| 入力ごとの主要 `% MOD` | 4 回 | 1 回 |
| 入力縮約 | `% MOD` | `Ai<2*MOD` を使う条件付き減算 |
| prefix 更新 | `% MOD` | 条件付き減算 |
| 最大ケース実時間 | 1.624638～1.637253 秒 | 1.381084～1.408911 秒 |
| 最大ケース平均 | 1.631596 秒 | 1.390362 秒 |
| Peak Working Set | 8.945～8.953 MiB | 9.266～9.289 MiB |
| コード物理行数 | 111 | 110 |
| 空行・コメント行を除く行数 | 88 | 91 |
| ファイルサイズ | 3,412 bytes | 3,439 bytes |

記事版の平均実時間は既存版より 0.241234 秒、17.35% 長い。主因は各入力で pair の
乗算・剰余を追加し、入力縮約と prefix 更新も `%` で素直に記述したことと推定する。
それでも 3.0 秒基準内であり、数式との対応が直接見える利点に対して許容できる差と判断した。

Peak Working Set は記事版の方が測定上わずかに小さいが、どちらも配列を持たない
`O(1)` 実装であり、この程度の差は実行環境のばらつきとして扱う。
