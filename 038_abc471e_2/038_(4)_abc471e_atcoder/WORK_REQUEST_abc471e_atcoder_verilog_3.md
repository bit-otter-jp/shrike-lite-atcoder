# ABC471E AtCoder Verilog - WORK_REQUEST_3

## 1. 目的

AtCoder提出用Verilogを、**速度最適化より可読性を優先した3レジスタ方式**へ作り直す。

記事本文へコード全文を掲載し、

```text
ライトユーザー:
    コピペしてそのまま動かせる

中級ユーザー以上:
    自分で高速化・改造して遊べる
```

形にする。

既存の最適化版はGitHub掲載用として保持し、上書きしない。

---

## 2. 基本方針

前編で説明した3つの集計値を、そのままコード上で管理する。

```text
prefix_sum
pair_sum
square_sum
```

入力値 `x` ごとに、概念的には次を行う。

```text
pair_sum   += prefix_sum * x
prefix_sum += x
square_sum += x * x
```

すべて `MOD = 998244353` で剰余を取る。

最終答えは、

```text
C(N-1,K-1) * square_sum
+ 2 * C(N-2,K-2) * pair_sum
```

を `MOD` で剰余したものとする。

公式解説の

```text
2 * pair_sum = prefix_sum^2 - square_sum
```

を使った2レジスタ化は、今回は行わない。

---

## 3. 可読性優先

今回の提出版では、WORK_REQUEST_1で行った細かい高速化を必須としない。

特に、

```text
Ai < 2*MOD を利用した条件付き減算
prefix_sum更新時の % 削減
pair_sum消去
```

は、可読性を損なうなら採用しない。

可能なら、

```verilog
x = a % MOD;
```

のように、意味が直接読める記述を優先する。

ただし、64bit overflowを起こさない整数幅は維持する。

---

## 4. コードの位置付け

この版は、

> 最速版

ではなく、

> 数式と実装の対応が分かりやすい、記事掲載用のプリミティブ版

とする。

読み手が前編の記事から、そのままコードを追えることを重視する。

過度な関数分割や抽象化も避け、1ファイルを読めば処理の流れが分かる形を目指す。

---

## 5. 組合せ係数

組合せ係数の実装は、既存版を基準にしてよい。

```text
C(N-1,K-1)
C(N-2,K-2)
```

を正しく求める。

既存最適化版で使用した、

```text
C(N-2,K-2)
= C(N-1,K-1) * (K-1) / (N-1)
```

を使ってもよいが、記事掲載版として著しく読みにくくなるなら、より素直な実装へ変更してよい。

変更した場合は正しさと実行時間を再確認する。

---

## 6. 正しさ検証

最低限、WORK_REQUEST_1と同等の検証を行う。

```text
公式サンプル       3件
境界ケース         9件
独立ランダム      300件
```

ランダムテストの期待値は、Verilog版の式を写さず、

```text
小さいNでK要素部分集合を全列挙
各部分集合の和を二乗
全結果を加算
```

する独立oracleを使用する。
